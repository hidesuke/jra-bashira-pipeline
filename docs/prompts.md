# プロンプト

プロンプトの本文は、非公開リポジトリ `hidesuke/jra-bashira-prompts` にだけ置きます。このファイルに書いてあるのは、Worker が KV から読む形と、user 文の差し込み名です。本文を KV へ入れる手順は、このリポジトリにはありません。

## KV の形

キーは `prompt:v2:course` と `prompt:v2:race` です。値は `{"version","system","user"}` です。`version`、`system`、`user` のいずれかが空なら、そのジョブは失敗します。以前の `{"text"}` だけの値は読みません。`text` が残っていても、読むのは `version`、`system`、`user` だけです。

Gemini は `system` を `systemInstruction`、`user` を `contents` の user メッセージに分けます。レース予想の応答は Markdown として読み、見出しから指数分布・自信度・波乱度・印を取ります。見出しが足りないときだけ、本文中の JSON を試します。取り方は [notion.md](notion.md) です。

## Gemini への渡し方

コース分析とレース予想の両方に、`generationConfig.thinkingConfig.thinkingLevel` を `high` と付けます。`includeThoughts` は付けません。`temperature` や `maxOutputTokens` など、思考レベル以外の `generationConfig` は付けません。思考レベルを上げると思考トークンが増え、`predict` の Queue consumer が 15 分の上限に当たりやすくなります。詳細は [pipeline.md](pipeline.md) です。

エンドポイントは `streamGenerateContent` で、クエリは `alt=sse` です。リクエスト本体は `generateContent` のときと同じです。コース分析とレース予想のどちらも `json` は付けません。`json` を付けたときだけ `responseMimeType` と `responseSchema` を足し、再試行できない失敗のときだけスキーマ無しでもう一度呼びます。届いた `parts` は順に連結し、`thought` が true の部分は本文に入れません。`finishReason` と `modelVersion` は最後に届いた文字列、`usageMetadata` は最後にそのフィールドが付いていたチャンク、`webSearchQueries` は最後に届いた配列です。HTTP の失敗メッセージはこれまでと同じです。ストリーム中のエラーと、途中で切れたストリームは失敗にし、再試行できるものは Queue の再試行に乗せます。

コース分析（`prompt:v2:course`）だけ、`tools` に `{ "googleSearch": {} }` を付けます。レース予想には付けません。

応答の `parts` のうち `thought` が true の部分は本文に連結しません。`groundingMetadata` の引用は本文に混ぜません。Notion の書式は変えません。

呼び出しごとに、ジョブ `job:v1:{raceKey}` の `gemini.course` または `gemini.race` へ残します。項目は `finishReason`、`modelVersion`、`usageMetadata`（`promptTokenCount`、`candidatesTokenCount`、`thoughtsTokenCount`、`totalTokenCount`）です。コース分析は加えて `webSearchQueryCount` と `webSearchQueries`（`groundingMetadata.webSearchQueries` の文字列）です。確認は [admin.md](admin.md) の `GET /admin/jobs` です。コース分析の記録は、レース予想が失敗しても残します。

Google 検索の料金は、使うモデルに依存します。3.8 Flash では月 5,000 クエリまで無料で、それを超えると 1,000 クエリあたり 14 ドルです。1 回のコース分析が複数クエリを使うことがあり、失敗後の再試行は同じコース分析をもう一度呼びます。思考トークンは出力として課金されるため、`high` は 1 呼び出しあたりの出力料金を増やします。モデル名はこの Worker では固定せず、KV `config:models` か `DEFAULT_MODEL` です。

user 文の差し込みは次の名前です。置換したあとに `{{` が残っていると（`{{name}}` も `{{#…#}}` も）ジョブは失敗します。KV を新しい名前へ替えるまでのあいだ、右の Dify ノード ID にも同じ値を入れます。天気の Dify トークンは、DSL の綴り `weathre` のままです。

枠・4角・馬場状態のコース集計（`stats:v2` のキャッシュ）は、どちらの user 文にも入れません。コース分析だけ、別に計算したコースデータ要約を `{{course_summary}}` で渡します。レース予想には、父・母の父・騎手のこのコースの成績を `{{runner_stats}}` で渡します。取り方は [course-odds.md](course-odds.md) です。

## コース特徴（`prompt:v2:course`）

| 差し込み | 入るもの | 出典 | 移行中の Dify トークン |
| --- | --- | --- | --- |
| `{{venue}}` | 競馬場 | リクエストの開催場（BASHIRA `get_races` の `race_track`） | `{{#1788717846587.course#}}` |
| `{{surface}}` | 芝 / ダート / 障害。無いときは「不明」 | BASHIRA `get_races` の `surface` | `{{#1788717846587.type#}}` |
| `{{distance}}` | 距離（メートルの数値）。無いときは「不明」 | BASHIRA `get_races` の `distance` | `{{#1788717846587.distance#}}` |
| `{{course_summary}}` | コースデータ要約。失敗したときは「コースデータ要約はありません（集計に失敗しました）。」 | コードが `get_stats` の件数から計算する。本文は [course-odds.md](course-odds.md) | なし |

`{{course_summary}}` を user にまだ書いていない KV でも、ジョブは進みます。書いてあるときだけ、要約が入ります。失敗したときは、表にある「コースデータ要約はありません（集計に失敗しました）。」が入ります。

プロンプト側（非公開リポジトリ `hidesuke/jra-bashira-prompts` のコース分析 user）に足すもの:

- user に `{{course_summary}}` を置く。
- コース分析の文章は、これまでどおりモデルの知識と Google 検索で書く、と指示する。
- 要約の件数と割合は計算済みなので、率を数え直さない。回収率は出さない。柵、種牡馬、母父、騎手の成績はこの要約に無い。
- 「開催が少ないため参考値」が付いた数字は、その注釈を残して使う。
- 差し込みが「コースデータ要約はありません（集計に失敗しました）。」のときは、件数や率を作らず、知識と検索だけで書く。

レース予想の user には、この差し込みを足しません。コース分析の本文を通して渡ります。

## レース情報（`{{race_facts}}`）

`{{race_facts}}` を user にまだ書いていない KV でも、ジョブは進みます。そのときは同じ本文をユーザー文の先頭に足します。user に `{{race_facts}}` があるときは、そこだけに入り、先頭には足しません。

本文は次の行です。値が無い行は、ラベルのあとを空にします。

- レース名（`race_name_main`。特別競走以外は空）
- グレード（`grade`。G1、G2、G3、L、その他重賞、平場。オープンはグレードではなくクラス）
- クラス（`race_condition`。新馬、未勝利、1勝クラス、オープンなど）
- 競走種別（`race_type`。3歳以上など）
- 頭数。`予定` は `scheduled_horse_count`。`出走` は `starters`（upcoming では予定から取消・除外を引いた数）。`starters` が空のときは、出馬表から取消・除外を除いて数える
- コース（`rail_type` の A〜D。A は本柵、B〜D は移動柵）
- 内外回りと仮柵。BASHIRA に項目が無いので、常に空欄
- 斤量種別（`weight_type`。ハンデ、別定、馬齢、定量）
- 発走時刻（`post_time`。秒が 00 のときは時分だけ）

末尾に、内外回りと仮柵が無い旨の注を付けます。内・外には読み替えません。オッズはこの本文に入れません。馬柱の行には、これまでどおり今回の単勝と人気を残します。今回の単勝を欄として渡すのは `{{win_odds}}` です。

空欄にした項目は、ジョブの `raceInputGaps` に残します。`GET /admin/jobs` の `race_input_gaps` と、`GET /admin/inspect` の同じ名前で見ます。予想は止めません。

プロンプト側（非公開リポジトリ `hidesuke/jra-bashira-prompts` のレース予想 user）に足すもの:

- user に `{{race_facts}}` を置く。置く場所を自分で決める。置くまで Worker が先頭に足す。
- 空欄の項目は推測で埋めない。内外回りと仮柵は空のままにする。
- 馬柱の各馬に増えた「調教師」「馬体重」の行を使う。括弧の美浦は東、栗東は西、招待はそのまま。馬体重の `増減—` は、発表前か前走が無い。
- プロンプトの version は MINOR を上げる。本文はこのリポジトリに置かない。

## 過去走（`{{past_runs}}`）

`{{past_runs}}` を user にまだ書いていない KV でも、ジョブは進みます。そのときは `{{race_facts}}` の次、ユーザー文の先頭側に足します。user に `{{past_runs}}` があるときは、そこだけに入り、先頭には足しません。二次予想がこの表と `{{course_records}}` と `{{runner_stats}}` だけを読む入口は、[admin.md](admin.md) の `include=past_runs` です。プロンプト本文は返しません。

本文は `# 過去走（近10走）` で始まり、馬は馬番の順です。見出しは `### 馬番 馬名` です。取消・除外の馬は出しません。同名で近走を特定できない馬は `同名馬のため近走取得不可` だけです。走が無い馬は `近走なし` です。

ある馬の表は、次の列の Markdown 表です。空の値は空欄です。

`日付`、`競馬場`、`レース名`、`グレード`、`クラス`、`馬場`、`距離`、`コース`（A〜D）、`馬場状態`、`頭数`、`着順`、`タイム`、`着差`（秒）、`上り3F`（馬の `last_3f_sec`）、`上り順位`、`通過`（1〜4角を `3-3-2-2`）、`騎手`、`乗替`（`あり` / `なし`。列が無いときは空欄）、`斤量`、`馬体重`、`増減`（正は `+`）、`馬番`、`間隔`（日）、`人気`、`単勝`、`前半3F`、`後半3F`、`条件`

`人気` は過去のレースの `win_odds_rank`、`単勝` は過去のレースの `win_odds` です。今回の単勝は入れません。`前半3F` と `後半3F` は、そのレースの `get_races` の `first_3f_sec` と `last_3f_sec`（秒）です。馬の上りとは別です。JRA の場コードが無い競馬場は、前半3Fと後半3Fを空欄にします。`race_meeting_date` が `2026-10-12T00:00:00Z` のように時刻付きでも、表の日付と `race_id` は `2026-10-12` にします。時刻付きのままでは 8 桁の日付にならず、`get_races` を呼ばないので前半3Fと後半3Fが全行空欄になります。秒が無いレース（障害の前半3F、場コードの無い競馬場）は、空欄のままにします。

`レース名` は `race_name_main` のままです。特別競走以外は空欄です。空欄は、特別競走ではないことを表し、0 や未出走ではありません。

`条件` は表の末尾です。ここまでの列の順番と意味は変えていません。特別競走かどうかに関係なく、`race_type` と `race_condition` が両方あるときだけ並べます。表記は `3歳以上2勝クラス`、`2歳未勝利`、`3歳以上オープン`、`障害3歳以上未勝利` です。種別の中のスペースは入れません。`500万円以下` を `1勝クラス` にはしません。どちらかが無い、または種別が一覧に無いときは空欄です。件数は [admin.md](admin.md) の `past_runs_missing` です。

1 行の例です。

`| 2026-10-12 | 東京 | 前走 | G3 | 3勝クラス | 芝 | 1600 | A | 良 | 16 | 2 | 1:33.2 | 0.2 | 33.8 | 1 | 3-3-2-2 | 騎手A | なし | 56 | 470 | -2 | 3 | 28 | 4 | 6.5 | 34.5 | 35.6 | 3歳以上3勝クラス |`

## コース成績（`{{course_records}}`）

`{{course_records}}` も、user に無いあいだは `{{past_runs}}` の次に足します。置いてあるときはそこだけです。

本文は `# コース成績` で始まり、次の行で何を足したかを書きます。馬の見出しは `### 馬番 馬名` です。各馬の3行は次の形です。

```
同じコース: (1,0,2,3,4,4)
同じ競馬場: (1,0,2,3,4,8)
関連コース: (0,1,1,0,0,2)
```

括弧の中は `1着,2着,3着,4着,5着,それ以外` です。空白は入れません。6着以下はそれ以外です。着順が付かない走（出走取消、発走除外、競走除外、競走中止、失格、落馬再騎乗）と、今回のレース、`upcoming`、開催日より未来の走は数えません。

- 同じコースは、今回と同じ競馬場、同じ芝かダート、同じ距離です。
- 同じ競馬場は、今回と同じ競馬場、同じ芝かダートです。距離は問いません。
- 関連コースは、コース分析が挙げた競馬場・芝かダート・距離の合算です。見出しの次に `関連コース: 東京,芝,2400 / 中京,芝,2200` と、数えた一覧を書きます。最大5件です。
- 内回り・外回りは区別しません。

一覧が読めないときは、見出しの行が `関連コース: 一覧が読めないため空欄` になり、各馬の `関連コース: ` は括弧を付けず空欄です。同じコースと同じ競馬場は数えます。一覧が空（ブロックはあり、行が無い）のときは `関連コース: なし` と、各馬 `(0,0,0,0,0,0)` です。同名で近走を特定できない馬は `同名馬のため成績を数えない` と、3行とも空欄です。

コース分析の出力末尾は、次のブロックです。行は `競馬場,芝かダート,距離` で、最大5行です。

```
<<<related-courses>>>
東京,芝,2400
中京,芝,2200
<<<end>>>
```

Worker はこのブロックを読んでから、`{{course_analysis}}` と Notion の `### コース分析` の両方から、ブロックと前後の空行を除きます。ブロックが無い、閉じていない、行が読めないときは予想を止めず、`raceInputGaps` に理由を残します。閉じていないときは、コース分析の本文は削りません。`GET /admin/inspect` のコース分析の出力全文は、削る前のモデル出力です。レース予想のユーザー文は、削ったあとの本文です。

## 出走馬のコース成績（`{{runner_stats}}`）

`{{runner_stats}}` を user にまだ書いていない KV でも、ジョブは進みます。そのときは `{{course_records}}` の次、ユーザー文の先頭側に足します。user に `{{runner_stats}}` があるときは、そこだけに入り、先頭には足しません。

本文は `# 出走馬のコース成績` で始まります。条件は今回の競馬場、芝かダートか障害、距離です。期間はレース日の前日までの過去 `STATS_PERIOD_YEARS` 年で、コースデータ要約と同じです。取消・除外の馬は出しません。馬の見出しは `### 馬番 馬名` です。

各馬の 3 行は、父、母の父、騎手です。取れた行は次の形です。勝率と複勝率はコードが件数から計算します。分母が 0 の率は `—` です。

`父 父一: 出走 48　勝ち 8　勝率 16.7%　複勝 20　複勝率 41.7%`

出走数が `COURSE_SUMMARY_MIN_COUNT` 未満のときは、同じ行の末尾に「件数が少ないため参考値」を付けます。既定は 30 です。名前が見つからない、同名で特定できない、呼び出しに失敗した、呼び出し上限で取れなかった、という行には件数を書きません。0 件とは書きません。解決できた名前で、そのコースの行が無いときだけ、出走 0 です。

見出しの近くに `scope` を書きます。2026-11-08 に同じ条件で `get_stats` を呼ぶと、`scope` は `jra_and_non_jra` でした。競馬場名で絞っているので、地方の同名場（別の名前）は入りません。`scope` がこれと違うとき、または応答に `scope` が無いときは、`raceInputGaps` に残します。件数は、読めればそのまま渡します。

`GET /admin/inspect` のレース予想のユーザー文と、`GET /admin/jobs/input` の `race_input` に、この本文が入ります。`include=past_runs` は、プロンプト文を除いたこの節だけを `runner_stats` で返します。欠けは `race_input_gaps` です。

プロンプト側（非公開リポジトリ `hidesuke/jra-bashira-prompts` のレース予想 user）に足すもの:

- user に `{{runner_stats}}` を置く。置く場所を自分で決める。置くまで Worker が `{{course_records}}` の次に足す。
- 勝率と複勝率は計算済みなので、数え直さない。「件数が少ないため参考値」が付いた数字は、その注釈を残して使う。
- 「取得できず」「名前が見つからない」「同名のため特定できない」の行は、0 件として扱わない。
- プロンプトの version は、非公開リポジトリで MINOR を上げる。本文はこのリポジトリに置かない。

## 今回の単勝（`{{win_odds}}`）

`{{win_odds}}` は、user に書いてあるときだけ入ります。書いていないプロンプトの先頭には足しません。馬柱の `今回単勝` の行は、これまでどおり残ります。

本文は次の形です。観測時刻は、行の中で最も遅い `odds_observed_at` を日本時間にした `YYYY-MM-DDTHH:mm:ss+09:00` です。種別は `odds_kind` です。どちらも無いときはラベルのあとが空です。

```
# 単勝オッズ
観測時刻: 2026-11-07T15:04:00+09:00
種別: 最終
1 ア: 3.1
2 イ: 1.2〜1.8
3 ウ: 
```

馬は馬番の順です。倍率は `odds`、範囲だけあるときは `最低〜最高` です。その馬の倍率が無いときは、コロンのあとが空です。取得そのものができないときも、馬の行は残し、倍率・観測時刻・種別を空にします。

プロンプト側（非公開リポジトリ）に足すもの:

- user に `{{past_runs}}`、`{{course_records}}`、`{{runner_stats}}`、`{{win_odds}}` を置く。置く場所を自分で決める。`{{past_runs}}` と `{{course_records}}` と `{{runner_stats}}` は、置くまで Worker が先頭に足す。順はレース情報、過去走、コース成績、出走馬のコース成績。`{{win_odds}}` は置くまで入らない。
- 短評に、関連コースの `(1着,2着,3着,4着,5着,それ以外)` を書く。同じコースと同じ競馬場も、この本文の行を使う。
- 短評と競馬新聞風印予想の各行に、今回の単勝を書く。空欄の馬は空欄のままにする。
- 見出しの順は、レース情報、レース総合判定、競馬新聞風印予想、買い目推奨・馬券戦術、予想の観点・注目ポイント、展開予想、コース分析、指数ランキングと短評。単勝オッズの見出しは出さない。
- プロンプトの version は MINOR を上げる。本文はこのリポジトリに置かない。

## 過去最高レースレベル

新しい `{{...}}` 差し込みはありません。`{{umabashira}}` に入る馬柱の末尾へ、別の節として連結します。user にこの節の差し込みを足す必要はありません。`{{` が残るとレース予想は止まるため、新しい差し込み名は使いません。

出すのは、次をすべて満たすレースだけです。判定は対象レースの `raceRow` です。

- `race_type` が `3歳`
- `race_condition` が `未勝利`（新馬は出さない）
- `grade` が G1、G2、G3、L のどれでもなく、`race_condition` がオープンではない
- `surface` が芝またはダート（障害は出さない）

対象でも、race の system にマーカー `<!-- input:race_level -->` が無いときは出しません。使い方の制限が書いていないプロンプトへ、データだけを渡さないためです。マーカーの有無だけを見ます。制限の本文はこのリポジトリに置きません。

対象外、またはマーカーが無いときは、KV の `c1:v1:*` を読みません。

値は共有マシンが `APP_KV` に書いたものを、この Worker が読むだけです。計算も書き込みもしません。

- `c1:v1:meta` は `asof`、`data_through`、`feat_key`、`feat_sha256` を持つ JSON です。`feat_key` は `c1:v1:feat:{asof}` です。
- `c1:v1:feat:{asof}` は、馬のキー `馬名|YYYY-MM-DD` に `display` を持つ JSON です。`display` はそのまま行にします。丸めや桁の整形はしません。
- 他の `c1:v1:*` は読みません。

馬は出馬表の `horse_name` と `birth_date` の先頭 10 文字で引きます。表に無い馬、生年月日が日付でない馬は `過去最高レースレベル 不明` です。取消・除外は出しません。`display` に `{{` がある馬は不明にし、ジョブは止めません。

`asof` が開催日の 9 日前より古いとき、開催日以降のとき、meta か feat が無いとき、壊れているときは、全頭を不明にします。理由は `raceInputGaps` に残します。開催日の 9 日前から開催日前日までだけ表を使います。範囲外のときは feat を読みません。

節の形は次です。先頭の数字は馬番です。基準日の行は meta の `data_through` です。

```
# 過去最高レースレベル（3歳未勝利のみ）
1 馬名A: 過去最高レースレベル 2.200（該当：...）
2 馬名B: 過去最高レースレベル 不明
（基準: 確定データ YYYY-MM-DD まで）
```

プロンプト側（非公開リポジトリ `hidesuke/jra-bashira-prompts` のレース予想 system）に足すもの:

- system にマーカー `<!-- input:race_level -->` を置く。置くまで Worker はこの節を出さない。
- この節の使い方の制限を、同じ system に書く。本文はこのリポジトリに置かない。
- user に新しい `{{...}}` は足さない。節は馬柱の末尾に付く。
- プロンプトの version は、非公開リポジトリで MINOR を上げる。

記録は `input:v1:{raceKey}` と `trace:v1:{raceKey}` の `raceLevel` です。項目は `applied`、`reason`、`asof`、`dataThrough`、`featSha256`、`horses`、`missing` です。マーカーが無いときは `reason` が `prompt_without_c1`、対象外は `not_applicable` です。新しいキーは作りません。見方は [admin.md](admin.md) の `GET /admin/inspect` です。

## 確認用に残すもの

予想の実行時に、コース分析へ渡したユーザー文と、コース分析・レース予想の出力全文を KV `trace:v1:{raceKey}` に残します。プロンプト版と、呼び出したモデル名も残します。レース予想の検索クエリは、ジョブの `gemini.race` には入れず、このキーにだけ残します。過去最高レースレベルの `raceLevel` も、この JSON と `input:v1:{raceKey}` に足します。別のキーは作りません。システムプロンプトの本文は残しません。

長い本文は 10 万文字ごとに `trace:v1:{raceKey}:cu:{n}`（コースのユーザー文）、`trace:v1:{raceKey}:co:{n}`（コースの出力）、`trace:v1:{raceKey}:ro:{n}`（レースの出力）へ分けます。1 項目が 50 万文字を超える分は切ります。馬柱とレース予想のユーザー文は `input:v1:{raceKey}` のままです。読み方は [admin.md](admin.md) の `GET /admin/inspect` です。
