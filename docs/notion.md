## ページの選び方

Dify 版と同じ開催日、競馬場、レース番号のページがあっても、本文のどこにも `BASHIRAで取得` が無いページは更新しません。新規ページを作ります。

ページ id は `notion:page:v1:{raceKey}` に保存します。再実行は、そのページのブロックを 1 件ずつ消して上書きしません。新しいページを作り、本文の追記が終わってから旧ページを `archived: true` でアーカイブします。旧ページが 404 のときは、アーカイブ済みとして先へ進みます。

判断は次のとおりです。

- この実行でページを作り始めたあとは、そのページ ID を続ける。日付、場、レースが違うときはエラーで止まる。保存したページが 404 のときだけ、下の通常の判断に戻る。
- 同じ開催日・場・レースの検索が打ち切られたときはエラーで止まる。検索は `page_size` 20 で、結果が 9 件以上、または `has_more` のときに打ち切りとみなす。見るのは先頭 8 件まで。
- 保存したページの日付、場、レースが違うときはエラーで止まる。
- 保存したページがあり、ほかにも `BASHIRAで取得` のページがあるときはエラーで止まる。
- 引き継ぐページ ID が無く、`BASHIRAで取得` のページが複数あるときはエラーで止まる。
- 引き継ぐページ ID が無く、`BASHIRAで取得` のページが 1 件あるときは、そのページを旧ページとしてアーカイブし、新しいページを作る。
- 該当が無ければ新しいページだけを作る。

`BASHIRAで取得` は本文の末尾の灰色フッターにあります。先頭の数ブロックだけを見るとフッターを見落とすので、ブロックを 100 件ずつ、最大 8 ページ（800 ブロック）まで見ます。その範囲にマーカーが無いページは、BASHIRA のページとは扱いません。

## 本文のブロック

本文は Dify の「Notion用にに出力整形」と同じ規則でブロックにします。予想本文の Markdown を見出し（`#` から `####`）、箇条書き（`- ` と `* `）、`**太字**`、区切り線（`---`、`***`、`___`）、コードブロックにします。`>` で始まる行は callout（💡、`gray_background`）にし、連続する行は改行で 1 つにまとめます。

各 rich_text は 2000 文字までです。コードのコメントでは、Dify は超過分を切り、この Worker は同じ装飾の続きとして残す、とあります。子ブロックの追加は 100 件ずつです。最初の 100 件はページ作成に含め、残りは追記します。

ページの並びは次です。予想本文のなかの見出しの順番は、モデルの出力のままです。Worker は並べ替えません。

1. 予想本文。
2. 本文に「競馬新聞風印予想」が無いとき、末尾に `### 競馬新聞風印予想` と印の箇条書き。
3. コース分析。本文に分析の先頭 80 文字が既にあるときは足さない。`### 指数ランキングと短評` があるときはその直前、無いときは末尾に置く。8000 文字を超える分は「…（コース分析を省略）」として切る。コース分析の末尾に付く関連コースの一覧（`<<<related-courses>>>` から `<<<end>>>`）と、その前後の空行は除く。閉じていない一覧は、本文を削らずに残す。
4. 区切り線のあと、灰色の段落でフッター。

`### 単勝オッズ` は出しません。倍率はフッターの観測と、レース予想の `{{win_odds}}` に残します。モデルが本文に書いた単勝は、その位置のままです。

モデルが出す見出しの目標順は、レース情報、レース総合判定、競馬新聞風印予想、買い目推奨・馬券戦術、予想の観点・注目ポイント、展開予想、コース分析、指数ランキングと短評です。この順を本文に書くのはプロンプト側です。

グレードが G1、G2、G3、L、OP のときだけ、タイトルに `アルゼンチン共和国杯（G2）` のように全角括弧で足します。平場、その他重賞、空、それ以外の文字列は付けません。タイトルに同じグレードの全角括弧か半角括弧が既にあるときは重ねません。
