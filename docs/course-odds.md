# コース集計、馬場、オッズ

## コース集計

`get_stats` の条件は開催場、馬場（芝、ダート、障害）、距離、開催年です。馬場がこの 3 つのどれでも無いときは、集計を作らずに止まります。期間の既定はレース年を含む過去 5 年（`STATS_PERIOD_YEARS`）です。レース年 2026 なら `race_year` の `gte` は 2022 です。`min_starts` の既定は 30、母父だけ 50 です。

指標は勝数（1 着の件数）、複勝圏（3 着以内の件数）、単勝払戻の合計です。

取るもの:

- 枠番（1 回、`bracket_number` で分ける）
- 4 コーナー順位を 4 回に分ける。1 から 3、4 から 6、7 から 10、11 以降
- 馬場状態（1 回、`track_condition` で分ける）
- そのレースの父（まとめて 1 回。父が一人もいなければ作らない）
- そのレースの母父（`min_starts` 50。一人もいなければ作らない）
- 騎手は 1 人ずつ 1 回。`race_abnormality` が「出走取消」「発走除外」「競走除外」の馬の騎手は除く

人気（`win_odds_rank`）では集計しません。集計条件にそのフィールドが入っていたら、実行前に止めます。該当行が 0 のタスクは「該当なし、または min_starts 未満」と注記します。

回りは `get_races` の `course_side` です。値は `内`、`外`、`外→内`、`内→外`、`なし` です。`内`、`外`、`外→内`、`内→外` のときは、枠番、4角、馬場状態、父、母父、騎手の `get_stats` に、同じ値の `course_side` フィルタを足します。`外→内` は外や内にまとめません。`なし` と、値が空か読めないときはフィルタを足しません。スキーマに `course_side` が無いときも足しません。`course_variant` は Notion のフッターのため、常に null です。`rail_type` は馬柱の近走と、レース予想の `{{race_facts}}` のコース（A〜D）に渡します。馬場 API の使用コースは備考に残します。仮柵は項目が無いので空欄です。A〜D は内・外に読み替えません。

母数が減っても、絞った回りを外して全体の数字には戻しません。このキャッシュは `min_starts`（枠など 30、母父 50）未満をこれまでどおり落とし、「該当なし、または min_starts 未満」と注記します。コースデータ要約と出走馬のコース成績は `min_starts` では落とさず、既存の参考値の注釈を付けたまま出します。

成績は KV に 7 日キャッシュします。キーは `stats:v2:{id}:{場}:{馬場}:{距離}:{開始年}:{min_starts}:{対象名}` です。回りで絞ったときだけ、末尾に `:side:{encodeURIComponent(course_side)}` を足します。`なし` と絞らない集計は、この末尾が無く、今のキーのままです。`id` は `bracket`、`corner:1-3`、`corner:4-6`、`corner:7-10`、`corner:11plus`、`track_condition`、`sire`、`broodmare_sire` です。騎手だけ `id` を `jockey` にまとめ、対象名で分けます。対象名は父、母父、騎手の名前を並べたもので、対象が無い集計は `-` です。キャッシュがあっても、その結果はプロンプトにも Notion にも渡しません。[pipeline.md](pipeline.md) を参照してください。

1 つの Queue メッセージで取るのは最大 8 件です。

## コースデータ要約

コース分析の user にだけ渡す要約です。上のキャッシュした集計（枠の細分、種牡馬、母父、騎手、払戻）とは別に作り、そちらの結果はプロンプトに入れません。

条件は、今回のレースと同じ競馬場、芝またはダート（障害も同じ呼び方）、距離です。距離はまとめません。`course_side` が `内`、`外`、`外→内`、`内→外` のときは、`get_stats` とレース数の `get_races` をその回りだけにします。全体、4角、上がり3F、枠、馬場状態も同じ回りです。枠の「内外」（1〜4枠と 5〜8枠）は回りとは別です。`なし` はフィルタを足しません。期間はレース日の前日を終点にした過去 `STATS_PERIOD_YEARS` 年で、開催年では切りません。レース日が 2026-11-08 で年数が 5 なら、2021-11-07 から 2026-11-07 です。終点の月日が無い年は、その月の末日にします。

絞ったあとにレース数や区分が `COURSE_SUMMARY_MIN_COUNT` 未満でも、数字は出し、「開催が少ないため参考値」を付けます。別の回りの件数を足しません。条件の次の行に、絞った旨か、`なし` で絞らない旨を書きます。

`get_stats` は率を返さないので、出走数と条件つきの件数を取り、勝率・複勝率・割合はコードで計算します。払戻は取りません。回収率、柵、種牡馬、母父、騎手は入れません。`min_starts` では落としません。件数が小さくても数字は出し、注釈を付けます。

呼び出しは、既存の BASHIRA と同じく Durable Object 経由です。`get_stats` は 1 回に 8 件までなので、次を 1 まとめにします。

- 全体の出走数、勝ち数、3着以内の数
- 4角の位置 4 回。先頭（1）、2〜4番手、5〜9番手、10番手以下。勝ち数と 3着以内の数
- 上がり3F最速（`is_fastest_last_3f`）の出走数と勝ち数
- 枠番ごとの出走数、勝ち数、3着以内の数。コードで 1〜4枠と 5〜8枠に足す
- 馬場状態ごとの勝ち数と、そのうち 4角4番手以内の数。コードで「良・稍重」と「重・不良」に足す

4角は `get_stats` の軸にできないので、範囲で絞った呼び出しに分けます。レース数は `get_stats` では数えられない（1 行が 1 出走で、レース ID の件数がない）ため、同じ条件の確定済みレースを `get_races`（`race_status` は `finished`、1 回の `limit` は 200）で数えます。勝ち数とは、同着の分だけ違います。`truncated` でスキーマに `offset` があるときは、`offset` に `row_count` を足して続きを取ります。`offset` が無い、または上限 2000 を超えて打ち切れたときは「N以上」と書き、開催が少ないとは扱いません。

注釈「開催が少ないため参考値」は、レース数が `COURSE_SUMMARY_MIN_COUNT` 未満のとき全体に、区分の件数がそれ未満のときその行に付けます。既定は 30 です。脚質の行は頭数、上がり3Fと枠は出走数、馬場状態は勝ち数を見ます。

失敗（スキーマが違う、`get_stats` が失敗、件数が読めない、など）のときは要約を空のままコース分析へ進みます。ジョブの `courseSummary.error` に理由が残り、`GET /admin/jobs` の `course_summary_error` に出ます。成功した要約の本文は `course_summary` に出ます。予想を止めるのは、これまでの収集と同じ失敗だけです。

## 出走馬のコース成績

レース予想の `{{runner_stats}}` です。上のキャッシュ（`stats:v2`。枠、4角、馬場状態、払戻、`min_starts`、開催年）とは別に作ります。そちらのキャッシュは、これまでどおりプロンプトに入れません。

条件はコースデータ要約と同じです。今回の競馬場、芝かダートか障害、距離、レース日の前日までの過去 `STATS_PERIOD_YEARS` 年です。`course_side` が `内`、`外`、`外→内`、`内→外` のときは父、母父、騎手をその回りだけにします。`なし` は足しません。距離はまとめません。`min_starts` では落としません。払戻と人気は取りません。指標は出走数（応答の `starts`）、勝ち数（1 着の件数）、3着以内の件数です。勝率と複勝率はコードで計算し、行には必ず件数を付けます。出走数が `COURSE_SUMMARY_MIN_COUNT` 未満の行には「件数が少ないため参考値」を付けます。回りで少なくなっても、その注釈のまま出し、別の回りは混ぜません。コースデータ要約の「開催が少ないため参考値」とは文言が違います。件数の下限の変数は同じです。

取るもの:

- そのレースの父。`dimensions` は `sire_name`、`filters.sire_name` は出走する馬の父を配列にする。1 回。父が一人もいなければ呼ばない
- そのレースの母の父。`broodmare_sire_name` で同じ。1 回
- 騎手。`jockey_name` は配列にすると OR で合算されるので、1 人ずつ。同じ騎手は 1 回にまとめる。取消・除外の馬は除く

名前の配列は 100 件までです。1 レースでは超えません。`name_resolution` が曖昧なときは、その応答の行は使いません（絞り込みが実行されていないためです）。問い合わせた名前に生年を足した候補（`同名 (1994)`）がちょうど 1 件のときだけ、その名前を配列に入れて 1 回だけ指定し直します。候補が複数、または別の馬への部分一致のときは、決め打ちしません。出馬表に父と母の父の生年は無いので、生年が 1 件に決まらない名前は欠けにします。見つからない名前（`status` が `not_found`）も欠けです。どちらも 0 件とは書きません。解決できた名前で、打ち切られておらず行が無いときだけ、出走 0 です。勝ち数や複勝数が読めない行も、0 にはしません。

騎手の結果は KV に 7 日（`STATS_CACHE_TTL_SECONDS`）置きます。キーは `jockey-course:v1:{data_version}:{場}:{馬場}:{距離}:{期間の始}:{期間の終}:{騎手}` です。回りで絞ったときだけ、末尾に `:side:{encodeURIComponent(course_side)}` を足します。`なし` と絞らない結果は、この末尾が無く、今のキーのままです。`data_version` は `get_stats` の応答に付く、週次更新の版です。予想の段では、このキーを読んでから、無い騎手だけ取ります。失敗と、上限で取れなかった結果はキャッシュしません。同名で特定できない結果と、見つからない結果はキャッシュします。

2026-11-08 に、京都ダート 1800、2021-11-07 から 2026-11-07、父の配列で `get_stats` を呼びました。`scope` は `jra_and_non_jra`、`data_version` は `20261108T091910Z` の形、`data_through` は `2026-11-03` でした。`race_track` の「京都」と「札幌（地方競馬）」は別の値なので、この条件の件数は中央のその競馬場の走です。`scope` が `jra_and_non_jra` でないときと、`scope` が応答に無いときは、`raceInputGaps` に残します。件数は読めれば渡します。

失敗しても予想は止めません。理由はジョブの `raceInputGaps` に残り、`GET /admin/jobs` の `race_input_gaps` と `GET /admin/inspect` に出ます。1 配送の呼び出しは [pipeline.md](pipeline.md) の上限です。Notion の書式には足しません。

## 馬場

馬場は `GET https://jra-dify-pipeline.hdsk.workers.dev/baba/latest` を、ジョブの最初に 1 回だけ取ります。応答の `venues[]` から、`venueName` がそのレースの開催場と一致する 1 件を使います。`fetchedAt` はそのまま残します。

同じアカウントの `workers.dev` へ Worker から global fetch すると届かず 404 になるため、`BABA` サービスバインディング（`jra-dify-pipeline`）があるときは `env.BABA.fetch` で取ります。バインディングが無いテストとローカルでは global fetch に戻します。サービスバインディングの 1 回も、Worker の外部 45 件に数えます。

失敗しても予想は続けます。HTTP ステータスと本文の先頭 200 文字を理由として残します。通信そのものが失敗したときも、そのメッセージを残して続けます。開催場が `venues` に無いときも続け、その旨を残します。

天気と馬場状態の優先順位、備考に入る項目は [prompts.md](prompts.md) です。

## 単勝オッズ

オッズは `get_odds` の単勝（`bet_type` は `win`、`race_id`、`limit` 50）です。種別（`odds_kind`）と観測時刻を日本時間でフッターに残します。取れないときは種別も時刻も「なし」と書きます。オッズが無くても予想は続けます。認可の失敗と、Durable Object の外部呼び出し上限だけは、オッズ不足として飲み込みません。

| 状況 | 理由 | 予想が使うもの |
| --- | --- | --- |
| `get_odds` が失敗し、出馬表に単勝がある | 詳細に、失敗したので出馬表の単勝を使った旨 | 出馬表の `win_odds` |
| `get_odds` が失敗し、出馬表にも単勝が無い。メッセージに「未発売」がある | 未発売 | なし |
| `get_odds` が失敗し、上のどちらでもない | 取得エラー | なし |
| 行が無く、注記に「データが無」または `2007-07-28` がある | オッズのデータが無い | なし |
| 行が無く、`live_as_of` が今より 6 時間以上古い | 取得エラー。取り込みの問題の可能性を詳細に書く | なし |
| 行が無い。上のどちらでもない | 未発売 | なし |
| 行はあるが倍率が無く、すべて `status` が `no_bets` | 発売票数なし | なし |
| 行はあるが倍率がある行が無い | 未発売 | なし |
| 倍率がある | なし（利用可能） | `get_odds` の行 |

観測時刻は行の中で最も遅い `odds_observed_at` を日本時間にしたものです。フッターの「オッズ: あり / なし（理由）」と、詳細があるときの「オッズ詳細」は [notion.md](notion.md) です。本文の `### 単勝オッズ` は出しません。同じ値はレース予想の `{{win_odds}}` に、馬ごとの行で渡します。差し込みの形は [prompts.md](prompts.md) です。
